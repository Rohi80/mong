# 감리교 청빙·구인 정보 통합 사이트 — 설계안 (v0.1)

> 참고 모델: `cheongbing.vercel.app/tonghap` (예장통합 청빙 공고 모아보기로 추정)
> 대상: 기독교대한감리회(KMC) 목회자·사역자 청빙/구인 정보

## 0. 전제와 가정

| 항목 | 내용 | 상태 |
|---|---|---|
| 참고 사이트 성격 | 도메인(`cheongbing` = 청빙, `tonghap` = 예장통합)으로 볼 때, 교단 홈페이지의 청빙 게시판을 수집해 검색·필터로 보여 주는 사이트로 추정 | **미확인** (작업 환경에서 접속 차단) |
| KMC 데이터 위치 | kmc.or.kr 안의 청빙·구인 관련 게시판. 회원 전용일 가능성이 있음 | **미확인** |
| 감리교 제도 특성 | 담임자는 감독의 **파송**으로 확정됨(파송제). 교회의 "청빙"은 그 앞 단계의 절차이므로, 용어와 화면 문구에 반영해야 함 | 확인 필요 (교리와 장정 최신판 기준) |

## 1단계 — 타당성 확인 (코드 작성 전)

1. **데이터 출처 조사**
   - kmc.or.kr: 청빙/구인 게시판이 있는지, 비로그인으로 열람되는지, 게시판 구조(목록 URL, 페이지 번호, 글 상세 URL 규칙)
   - 연회 홈페이지(서울·중부·경기 등 각 연회): 자체 청빙 게시판 여부
   - 교단지(기독교타임즈) 청빙 광고란
2. **이용 조건 확인**
   - 사이트 이용약관·robots.txt
   - **회원 전용 글을 로그인해서 수집한 뒤 공개 사이트에 다시 게시하는 것은 하지 않는다.** 약관 위반 소지가 있고, 담당자 연락처 같은 개인정보가 포함됨
   - 가능하면 총회본부(홍보·정보 담당 부서)에 사전 문의 또는 협조 요청
3. **판정 기준**
   - 공개 게시판이 있으면 → 2단계 A안(수집형)
   - 회원 전용뿐이면 → 2단계 B안(제보·등록형) 또는 본부 협조

## 2단계 — 운영 방식 선택

| | A안: 공개 게시판 수집형 | B안: 직접 등록형 | C안: 혼합형 (권장) |
|---|---|---|---|
| 방식 | 공개 글 목록을 주기적으로 수집 | 교회가 폼으로 직접 공고 등록 | 수집된 공개 글 + 직접 등록 |
| 본문 처리 | 요약 필드 + **원문 링크** (본문 복제 최소화) | 등록자가 동의한 범위만 노출 | 출처별로 구분 표시 |
| 장점 | 초기 데이터가 바로 확보됨 | 법적 부담이 적음, 정보 품질 높음 | 초기 데이터 + 장기 지속성 |
| 단점 | 출처 사이트 구조가 바뀌면 깨짐 | 초기에 글이 적음 | 관리 포인트 증가 |

## 3단계 — 데이터 모델 (공고 1건)

```text
Posting
├─ id, source (kmc | 연회명 | 직접등록), source_url
├─ title, church_name
├─ annual_conference (연회), district (지방)
├─ region (시/도, 시/군/구)  ← 지도·지역 필터용
├─ position: 담임자 | 부담임자 | 전도사 | 교육전도사 | 기타
├─ employment: 전임 | 파트타임
├─ qualifications: 정회원/준회원/수련목회자 요건, 학력, 연령 등 (원문에서 추출한 짧은 텍스트)
├─ deadline (마감일), posted_at (게시일)
├─ status: 진행중 | 마감 (마감일로 자동 계산)
└─ fetched_at, hash (중복·변경 감지용)
```

- 감리회 직제 용어(정회원·준회원·수련목회자·담임자·부담임자 등)는 **교리와 장정 최신판**의 표기를 기준으로 고정 목록화
- 연회·지방 목록은 별도 마스터 테이블로 관리

## 4단계 — 기술 구성

```text
[수집기] GitHub Actions 크론 (예: 하루 2~4회)
   │  게시판 목록 → 새 글만 상세 조회 → 필드 추출 → 정규화
   ▼
[저장소] postings.json (초기)  →  Supabase/Postgres (등록 기능 추가 시)
   ▼
[웹] Next.js (정적 생성 + 주기적 재빌드)  →  Vercel 배포
```

- 초기에는 **DB 없이 JSON 파일 + 정적 사이트**로 시작 (비용 0원, 운영 단순)
- 수집 부하 최소화: 요청 간격 두기, 새 글만 조회, User-Agent에 사이트 이름·연락처 명시
- 로그인 자격 증명은 코드·저장소에 절대 넣지 않음

## 5단계 — 화면 구성 (MVP)

1. **목록**: 최신순 카드/표, 마감 임박 강조
2. **필터**: 연회 · 지역 · 직분(담임자/부담임자/전도사…) · 전임/파트 · 진행중만 보기
3. **검색**: 교회명·제목·키워드
4. **상세**: 요약 정보 + "원문 보기" 링크 (본문 전체 복제 지양)
5. **안내 페이지**: 데이터 출처, 수집 주기, 삭제 요청 방법, 파송제 관련 안내 문구

## 6단계 — 이후 확장 (선택)

- 새 공고 알림: 카카오톡 채널 / 이메일 / RSS
- 교회 직접 등록 폼 (B안)
- 지도 보기
- 통계: 연회별·직분별 공고 추이
